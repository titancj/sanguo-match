# 三国锦囊 · 三消游戏（Royal Match-like 原型）

> 本README面向Codex/开发代理。目标：在现有HTML原型基础上，持续迭代出一个面向东亚及东南亚市场、品质对标Royal Match核心体验的三消游戏。
> **运行环境只需 Node.js ≥ 18 + 现代浏览器，不需要任何本地AI模型。**

---

## 1. 当前状态（P0完成版）

- `index.html`（Canvas渲染，无外部依赖）运行时加载 `levels.json`，改关卡不碰游戏代码
- 已实现：5种棋子滑动交换、三消与连锁、特效道具（4连→火箭 / T·L形→火药桶 / 5连→锦囊妙计）、道具点按施放、道具互换组合技（火箭+火箭=十字、炸弹+火箭=三行三列、锦囊+锦囊=全屏）、粮草箱障碍（2HP，邻接消除受伤）、铁索连环、传国玉玺落底收集、预置火箭、分段重力补块、步数/目标/三星结算、选关军图、localStorage进度保存、粒子/震屏/合成音效/震动反馈
- 关卡数：**40关**（12种阵型轮换，三国回目命名；每10关一个烽火关）
- 验收命令：`node sim/bot.js` 输出40关通过率表；当前默认60局/关，结果为 `40/40 levels inside target band`
- 冒烟命令：`node sim/smoke.js` 验证关卡加载、军图渲染、首关启动

## 2. 核心方法论：bot模拟调难度（本项目的技术护城河）

行业做法（King 2018年发表过Human-like Playtesting相关研究）：不靠人肉试玩，
用脚本bot把每一关自动玩 N 遍，统计通过率，反向调整步数/目标数值，
使通过率落入设计目标带。**全程纯计算，无需GPU、无需模型。**

### 2.1 架构（三个文件解耦）

```
/game
├── index.html        # 游戏本体。所有逻辑函数必须保持"纯逻辑可无头运行"
├── sim/stub.js       # 最小DOM/Canvas桩（已有可用版本，见v1测试代码）
├── sim/bot.js        # 启发式bot + 蒙特卡洛跑批 + 步数自动调参
└── levels.json       # 关卡配置（从HTML中抽离，调参脚本读写此文件）
```

关键工程约束（违反则模拟失效）：
1. 游戏逻辑与渲染分离：`findMatches / gravity / trySwap / expandClears` 不得直接依赖真实DOM
2. 全局 `SIM` 开关：`SIM=true` 时 `sleep()` 立即resolve、粒子/音效/震动直接return
3. 关卡=纯数据：阵型用8×8字符画（`.`普通 `B`箱2血 `b`箱1血 `L`铁索 `R`预置火箭），目标/步数/颜色数全部进 `levels.json`

### 2.2 bot策略（启发式即可，不要上模型）

每步枚举所有合法交换，对每个候选：临时交换→`findMatches()`评分→换回。
评分 = 消除格数 + 1.5×目标相关格数 + 4×(可生成特效) + 道具激活奖励(8~20)。
从得分前3的候选中随机选1个（模拟真人非最优），无解时依赖游戏内洗牌机制。

### 2.3 调参循环

```
对每一关：
  跑 40~100 局 → 得通过率 rate
  若 rate > 目标+0.10 → 步数 -= round((rate-目标)×10)
  若 rate < 目标-0.10 → 步数 += round((目标-rate)×10)
  重复 ≤3 轮，步数夹在 [14, 45]
```

目标通过率曲线（Royal Match式锯齿）：
- 第1-3关 ≈ 90%（教学，不许挫败）
- 第4-9关 ≈ 75-85%
- 常规关 ≈ 50-65%，缓慢下行
- 每第10关 = 烽火关（Hard），≈ 30-35%，制造付费/道具使用动机

**已知局限（必须写进认知）：bot通过率是真人通过率的代理指标，相对排序可信、
绝对值不可信。上线后必须用真实玩家漏斗数据二次校准。**

## 5. 风险与诚实声明

- bot绝对通过率与真人有系统性偏差，相对难度排序可信
- 三国题材在日本市场认知度高（光荣《三國志》系列长年耕耘），在泰国/越南亦有受众基础；但"题材熟悉"≠"会下载三消"，需投放测试验证（此为推测，无数据支撑）
- Royal Match的护城河在百人级内容产能与买量体系，本项目对标的是其**单局体验品质**，不是其商业体量
